Qué ocurrió

General Analysis demostró que un ticket de soporte con instrucciones ocultas podía hacer que un agente de Cursor, conectado a Supabase vía MCP con un rol de servicio, leyera la tabla integration_tokens y escribiera los secretos en el ticket.

Impacto: Exfiltración demostrada de tokens de integración desde un proyecto de prueba; el patrón aplica a cualquier agente con acceso de rol de servicio a la base de datos

Quién lo provocó

Actor: General Analysis

Atribución: Prueba de concepto pública; Supabase respondió con documentación y cambios en los valores por defecto

Motivo: Investigación de seguridad

Cómo ocurrió

Vector de ataque: Inyección indirecta de prompts en el texto de un ticket enviado por un usuario y procesado por un agente con acceso privilegiado a la base de datos y capacidad de escritura

Causa raíz: La conexión MCP se ejecutaba con un rol que eludía la seguridad a nivel de fila y podía tanto leer tablas privadas como escribir registros visibles para el atacante

Cronología

  1. 6 jul 2025General Analysis publica la demostración
  2. jul 2025Supabase convierte el modo de solo lectura con alcance por proyecto en el valor por defecto documentado

Respuesta

Supabase recomendó el modo de solo lectura y añadió guías; no se reportó ninguna brecha en clientes

Estado actual: Parcheado
