Ce qui s’est passé

Une faille « fail-open » dans une application d'agents écrite par IA a exposé l'outil d'un chercheur sur Internet ; un attaquant a demandé à un agent de révéler la clé API du compte de modèles publics de METR et l'a utilisée pendant trois semaines. Selon METR, ces crédits gratuits auraient valu environ 600 000 $ et aucune donnée sensible n'a été consultée.

Impact: Environ trois semaines d'utilisation non autorisée du compte de modèles publics de METR. Les crédits, offerts par le développeur du modèle, auraient valu environ 600 000 $. METR n'a trouvé aucune preuve d'accès à des données sensibles de modèles.

Qui l’a déclenché

Acteur: Attaquant externe inconnu

Attribution: METR ne nomme pas l'attaquant ; elle pense que l'application a été repérée grâce aux sites récemment enregistrés dans les journaux de transparence des certificats.

Mobile: Utilisation gratuite de capacité de calcul de modèles d'IA (déduit)

Comment c’est arrivé

Vecteur d’attaque: Une application d'agents « vibe-codée » sur l'instance EC2 personnelle d'un chercheur contenait une faille qui désactivait silencieusement son authentification Google pendant plusieurs jours ; l'attaquant a demandé à un agent de révéler la clé API et a ajouté une clé SSH pour garder l'accès.

Cause racine: Identifiants de METR stockés sur une infrastructure personnelle hors de METR ; bug d'authentification dans une application écrite par IA ; aucune alerte de dépenses sur les crédits offerts.

Chronologie

  1. mars 2026L'attaquant accède à l'application exposée et récupère la clé API ; l'utilisation non autorisée dure environ trois semaines
  2. mai 2026Lors d'un incident distinct, une campagne de sondage vise l'infrastructure publique de METR ; un chercheur signale un bug sur un point d'accès SQL en lecture seule, que METR met hors ligne en versant une prime, sans signe d'accès à des données non publiques
  3. 31 août 2026METR publie une mise à jour de sécurité décrivant les deux incidents
  4. sept. 2026Couverture de presse, notamment The Hacker News et Infosecurity Magazine

Réponse

METR a relié le pic d'utilisation à l'instance et coupé l'accès, interdit les identifiants METR sur des infrastructures externes, instauré des revues de sécurité pour les applications publiques, des alertes de dépenses et une surveillance des clés, et recruté un responsable sécurité.
